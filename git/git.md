# git merge 和 git rebase

## 1. git merge 的作用

git merge 用于将两个分支的提交历史合并在一起。它会创建一个新的 "合并提交"（merge commit），保留两个分支的完整历史记录。

**主要特点：**
- 保留完整的分支历史和提交顺序
- 生成一个新的 merge commit，记录合并操作
- 非破坏性操作，不会改写已有提交
- 适合多人协作的公共分支

**常见用法：**
```bash
git checkout main
git merge feature
```

## 2. git rebase 的作用

git rebase 用于将当前分支的提交"移植"到目标分支的最新提交之后。它会重写提交历史，使提交线看起来更线性、更整洁。

**主要特点：**
- 创造一条线性的提交历史，没有分叉
- 会改写提交的 SHA-1 值（相当于新建提交）
- 使历史记录更清晰易读
- 适合在个人分支上整理提交

**常见用法：**
```bash
git checkout feature
git rebase main
```

## 3. 什么时候用 git rebase，什么时候用 git merge

### 使用 git merge 的场景：

- **公共分支合并**：将 feature 分支合并到 main / master 等共享分支时
- **需要保留完整历史**：当分支的完整演进过程对团队有价值时
- **多人协作的分支**：任何他人也可能基于此分支工作的场景
- **解决复杂冲突**：merge 只在合并那一刻解决一次冲突，更可控

### 使用 git rebase 的场景：

- **个人分支整理**：在将 feature 分支合并到主分支之前，先用 rebase 整理提交历史
- **保持历史线性整洁**：希望提交记录是一条直线、方便 code review 和 bisect 排查
- **同步上游变更**：在 feature 分支开发期间，用 rebase 拉取最新的 main 分支代码
- **清理本地提交**：合并多个零散的 WIP 提交为有意义的提交

### 黄金法则：

> **永远不要对已经推送到远程的公共分支执行 rebase。**

因为 rebase 会改写提交历史，如果其他人已经基于这些提交进行了开发，会导致严重的协作问题。
