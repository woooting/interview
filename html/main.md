# 语义化标签

1. **定义语义化标签：** "语义化标签是指HTML中那些具有明确含义和用途的标签，它们不仅能告诉浏览器如何显示内容，更重要的是能清晰地表达内容的含义和结构。"

   

2. **语义化标签的优势：**

   

   使用语义化标签的优势有一下几点：

   - **更好的可读性**：代码更易于理解和维护

   - **更佳的SEO**：搜索引擎能更好地理解页面内容

   - **更强的可访问性**：辅助技术(如屏幕阅读器)能更准确地解读页面

   - **更清晰的文档结构**：使页面层次更加分明"

     

3. **常见语义化标签举例**：

   

   - `header`:表示页眉或内容区块的头部

   - `<nav>`定义导航链接
   - `<main>`表示文档的主要内容
   - `<section>`定义文档中的节或段
   - `<aside>`表示与周围内容相关但不直接相关的内容
   - `<footer>`表示页脚或内容区块的底部"

   

4. **与传统div布局的对比：**

   

    "相比传统的div+class命名方式，语义化标签：

   - 使HTML结构更直观

   - 减少了不必要的class命名

   - 提供了更丰富的文档结构信息

     

5. **实际应用建议：**

   1. 优先使用合适的语义化标签
   2. 只在没有合适语义标签时使用div
   3. 结合ARIA属性进一步增强可访问性
   4. 确保标签的嵌套关系合理"

# 块级元素和行内元素及其区别

1. **定义及其特性**

   **块级元素：**独占一行，大小可控，上下左右都能撑

   - **独占一行**，默认从上到下垂直排列
   - **宽度默认填满父容器**（即 `width: 100%`）
   - 可以设置 `width`、`height`、`margin`、`padding`，并且上下边距会正常撑开
   - 可以容纳行内元素和其他块级元素

   

   **行内元素**：并肩同行，大小内容定，上下边距不听话

   - **不换行**，多个行内元素在同一行水平排列，直到一行排满才换行
   - **宽度和高度由内容决定**，不能直接设置 `width` / `height`（设置无效）
   - 只能设置**左右**的 `margin` 和 `padding`，上下 `margin` / `padding` 不会影响布局（但上下 `padding` 可能背景可见，不撑开实际行高）
   - 一般只容纳行内元素或文本，不能容纳块级元素（特殊元素如 `<a>` 可包裹块级在 HTML5 中允许，但需注意合规性）

2. **常见标签**

   

   **块级常用标签：**

   |          `<div>`          |         最通用的块级容器，无语义，常用来布局分区。         |
   | :-----------------------: | :--------------------------------------------------------: |
   |           `<p>`           | 段落，上下有默认边距，内部不能包含块级元素（如 `<div>`）。 |
   |      `<h1>` ~ `<h6>`      |        标题，自带上下边距及加粗，层次表示文档结构。        |
   |      `<ul>` / `<ol>`      |        无序/有序列表，默认带内边距和项目符号/编号。        |
   |          `<li>`           |      列表项，也是块级，通常位于 `<ul>` 或 `<ol>` 内。      |
   |  `<header>` / `<footer>`  |            页眉/页脚，语义块级，用于区分区域。             |
   | `<section>` / `<article>` |            章节/文章，语义块级，用于内容分区。             |
   |          `<nav>`          |                  导航链接区域，语义块级。                  |
   |          `<hr>`           |               水平分割线，自闭和标签，块级。               |

   ​	

   **行内常用标签：**

   |     标签      |                           特性说明                           |
   | :-----------: | :----------------------------------------------------------: |
   |   `<span>`    |     通用行内容器，无语义，常用于包裹部分文本或行内样式。     |
   |     `<a>`     | 超链接，默认带下划线（CSS可改），支持 `href` 属性；HTML5 中可包裹块级元素。 |
   |  `<strong>`   |             表示重要性/强强调，通常显示为加粗。              |
   |    `<em>`     |                  表示强调，通常显示为斜体。                  |
   | `<b>` / `<i>` |      仅是视觉上粗体/斜体，无语义，不推荐用于重要强调。       |
   |    `<img>`    | **替换行内元素**（特殊：可设置宽高），默认按基线对齐，有内部尺寸。 |
   |    `<br>`     |                换行符，自闭和，用于强制换行。                |
   |   `<code>`    |                 展示代码片段，通常等宽字体。                 |
   |     `<q>`     |                    短引用，自动添加引号。                    |

3. **区别**

   | 特性       | 块级元素                       | 行内元素                            |
   | :--------- | :----------------------------- | :---------------------------------- |
   | 换行行为   | 独占一行                       | 与其他行内元素共享一行              |
   | 宽高设置   | 可设置 `width` / `height`      | 设置无效                            |
   | 上下外边距 | 生效                           | 不生效（左右生效）                  |
   | 上下内边距 | 生效，会撑开父容器             | 视觉效果可能重叠，但不影响周围布局  |
   | 默认宽度   | 100% 父容器                    | 由内容撑开                          |
   | 容纳范围   | 可包含块级和行内               | 一般只包含行内或文本                |
    | 常见例子   | `<div>`, `<p>`, `<h1>`, `<ul>` | `<span>`, `<a>`, `<strong>`, `<em>` |

# src和href的区别

```html
<link href="styles.css" rel="stylesheet">
<script src="app.js"></script>
```

 两段代码**分别是对外部css和js资源的引用**，但是引用的方式却不相同



1. **核心区别：**

    `src` **直接嵌入并替换当前元素内容**（如JS执行、图片显示），而 `href` **建立与外部资源的关联关系**（如CSS应用、链接跳转）

   **本质差异：**
   `src` 是 **"把资源拿过来用"** ，`href` 是 **"告诉浏览器这个资源和我有关"** 。

   **嵌入：**在页面上直接呈现，例如图片设置 **src** 你可以直接在网页上看到该资源

   ```
    <img src="http://gips3.baidu.com/it/u=1022347589,1106887837&fm=3028&app=3028&f=JPEG&fmt=auto?w=960&h=1280" alt="" width="100px" height="100px">
   ```

   **关联：** 通过某种映射关系，使得两者有相关性，比如超链接中使用 **href** 就是说明这个该文本和这个链接有关，点击后会产生副作用

   ```
    <a href="http://gips3.baidu.com/it/u=1022347589,1106887837&fm=3028&app=3028&f=JPEG&fmt=auto?w=960&h=1280">点击下载图片</a>
   ```

   ​	

   **那么为什么 CSS 资源使用的是 Herf 而 JavaScript 资源使用的 Src 呢？**

   ​	CSS**定义是重叠样式表** ，他是一种 **规则** 他不改变文档结构只是修饰DOM表现形式，换句话说就是CSS不会更改DOM

   ​    JavaScript 可能会动态修改DOM，即改变**文档结构或行为**，比如删除或新增DOM 

   那么从语义化上理解“**嵌入**”，必然会改变文档，而“**关联**”只是说明两者存在相关性，不存在改变的意思

    

2. **性能区别**

| 对比项    | `src`                            | `href`                           |
| :-------- | :------------------------------- | :------------------------------- |
| 加载方式  | 同步加载（默认阻塞渲染）         | 异步加载（不阻塞 DOM 解析）      |
| 执行/渲染 | 立即生效（如执行 JS、显示图片）  | 按需生效（如点击链接、应用 CSS） |
| 缓存策略  | 强缓存优先（如 `Cache-Control`） | 协商缓存优先（如 `ETag`）        |
| 错误影响  | 可能导致元素失效（如图片裂图）   | 通常降级处理（如 CSS 加载失败）  |

注：`src` 常用于 `<img>`、`<script>`、`<iframe>` 等；`href` 常用于 `<a>`、`<link>` 等。

1.  **下载方式的区别**

    

   **“嵌入资源”** 往往是同步加载的，这意味着，当浏览器解析到该资源时可能会阻塞DOM树的构建

   除非你使用defer和async来控制 **JavaScript文件** 下载时机，当浏览器解析该资源时，进行异步下载，此时不会阻塞HTML解析

   ```
   浏览器遇到资源标签时有两步工作 1.下载资源 2.解析资源(执行)
   <!-- 异步下载，下载完后立即执行 -->
   <script src="script.js" async></script>
   
   <!-- 异步下载，等待HTML解析完成后执行 -->
   <script src="script.js" defer></script>
   
   <!-- 默认同步阻塞 -->
   <script src="script.js"></script>
   ```

   

    **“关联资源”**往往是异步加载的，浏览器下载资源完成后，解析资源时会构建CSSOM树，这个过程是异步不阻塞DOM构建的

   但如果这个过程耗费时间太长，会阻塞浏览器合成**Render-Tree**，导致页面白屏。(在浏览器章节会介绍这个知识)

   ```
   <!-- 标准方式：同步加载，阻塞渲染（推荐） -->
   <link rel="stylesheet" href="style.css">
   
   <!-- 异步加载方式1：使用 media 属性（先低优先级，加载完后自动应用） -->
   <link rel="stylesheet" href="async-style.css" media="print" onload="this.media='all'">
   
   <!-- 异步加载方式2：使用 preload（预加载但不立即应用） -->
   <link rel="preload" href="critical.css" as="style" onload="this.rel='stylesheet'">
   <noscript><link rel="stylesheet" href="critical.css"></noscript>
   ```

   

2. **缓存策略的区别**

   

   浏览器对 `src` 资源倾向于使用**强缓存**

   - 优先使用 `Cache-Control: max-age`
   - 适合不变资源（如图片、静态JS）

   ```
   <!-- 图片可能被长期缓存 -->
   <img src="logo.png" alt="公司标志">
   ```

   

    `href` 资源更多使用**协商缓存**：

   - 优先使用 `ETag`/`Last-Modified`
   - 适合频繁更新的资源（如CSS）

   ```
   <!-- CSS 经常使用ETag验证 -->
   <link href="styles.css" rel="stylesheet">
   ```

   

3. **错误处理的区别**

   	**src 资源错误** 加载失败会直接影响功能：

```html
<!-- 图片加载失败会显示alt文本 -->
<img src="missing.jpg" alt="图片缺失提示">

<!-- JS加载失败会中断后续脚本 -->
<script src="missing.js"></script>
```

​		

​	**href 资源错误 **加载失败通常有优雅降级

```html
<!-- CSS加载失败会使用浏览器默认样式 -->
<link href="missing.css" rel="stylesheet">

<!-- 链接失效会显示404页面 -->
<a href="deleted.html">已删除的页面</a>
```

# `<script>`标签中的Async 与Defer 的区别

script 标签的 defer 和 async 属性，**是为解决传统脚本加载阻塞 HTML 解析的问题而生**。**传统方式中，脚本加载执行会暂停 HTML 解析，易致白屏或 DOM 操作错误。** defer 让脚本并行加载，等 HTML 解析完按顺序执行，适合需操作 DOM 或有依赖的脚本；async 使脚本并行加载，完成后立即执行，顺序不定，适合独立脚本。**二者提升了加载效率，优化了用户体验。**

HTML 中，`<script>`标签的`defer`和`async`属性都用于**控制脚本的加载和执行时机**，但它们有以下区别：

1. **加载方式**
   - `defer`：脚本会与 HTML 并行加载，但会**等到 HTML 解析完成后（DOMContentLoaded 事件触发前）才执行**。
   - `async`：脚本会与 HTML 并行加载，**加载完成后立即执行，可能会打断 HTML 的解析**。
2. **执行顺序**
   - `defer`：多个带`defer`的脚本**会按照它们在 HTML 中出现的顺序执行**。
   - `async`：多个带`async`的脚本**执行顺序不确定，先加载完成的先执行**。
3. **适用场景**
   - **`defer`：适用于需要在 DOM 加载完成后执行，但顺序很重要的脚本，如操作 DOM 的库或框架。**
   - **`async`：适用于独立的、不依赖其他脚本和 DOM 的脚本，如广告、分析脚本。**

```html
<!DOCTYPE html>
<html>
<head>
    <!-- 1. 正常脚本：立即加载并执行，阻塞HTML解析 -->
    <script src="script1.js"></script>

    <!-- 2. defer脚本：并行加载，按顺序执行，HTML解析完成后 -->
    <script defer src="script2.js"></script>

    <!-- 3. async脚本：并行加载，加载完成立即执行，顺序不确定 -->
    <script async src="script3.js"></script>
</head>
<body>
    <!-- 页面内容 -->
</body>
</html>
```

执行流程大致为：

```markdown
script1.js 会阻塞 HTML 解析
script2.js 和 script3.js 会并行加载
script3.js 可能在 HTML 解析完成前执行（如果加载快）
script2.js 会在 HTML 解析完成后，按顺序执行（无论何时加载完成）
```

# 盒模型

1. **定义**

   - box-sizing: content-box

      `width`和`height`只包含内容(content)

   - box-sizing: border-box

      `width`和`height`包含内容(content)、内边距(padding)和边框(border)

2. **应用场景**

   1. 标准盒模型

      **特点**：`width` / `height` 包含**内容、内边距、边框**，实际占宽 = `width`。

      - **精确控制内容区尺寸**：当元素的内容需要固定宽高（如图片、视频、特定容器），且内外边距可独立调整时。
      - **原生表单元素**：`<input>`、`<button>` 等默认 `content-box`，因为它们的尺寸通常基于内容区域。
      - **与旧设计稿对齐**：部分设计系统严格按内容区域标注尺寸，直接使用 `content-box` 更匹配。
      - **避免全局样式干扰**：某些组件内部需要完全独立于外部盒模型时，可局部使用 `content-box`。

   2. IE 盒模型

      - **响应式网格/栅格系统**（最常用）：例如 `width: 33.33%` + `padding` + `border` 不会撑破父容器，完美适配弹性布局。
      - **全局重置（推荐）**：几乎所有现代项目都会使用 `* { box-sizing: border-box; }` 让布局更直观，避免嵌套宽度溢出。
      - **组件库 / 框架内部**：Bootstrap、Tailwind、Ant Design 等默认使用 `border-box`，确保组件尺寸一致。
      - **需要同时设置 `width`、`padding`、`border`** 时最省心，不需要额外计算总宽度。
      - **百分比 + 固定边距混合布局**：如父容器 `width: 100%`，子元素 `width: 50%` 再加 `padding: 10px`，使用 `border-box` 可自动容纳。

3. **关键特性：**

   1. **外边距合并**

      - 相邻元素的垂直外边距会合并为较大的一个。

      - ```html
        <div style="margin-bottom: 20px;">元素1</div>
        <div style="margin-top: 10px;">元素2</div>
        
        //元素 1 和元素 2 之间的实际间距为 20px（取较大值）。
        ```

   2. **内边距和边框不影响元素的位置**

      - 增加内边距和边框会撑大元素，但不会改变其他元素的位置（除非超出父元素）。

   3. **负外边距：**			

      - 可用于将元素拉向其他元素，例如：`margin-top: -10px` 会使元素向上移动 10px。

# `meta viewport` 的作用和 `meta`

在移动端浏览器中，`<meta name="viewport">` 用于**控制视口（viewport）的宽度、缩放比例以及用户缩放行为**，从而让网页在不同尺寸的屏幕上获得更好的显示效果。(**移动端适配**)

 **完整参数说明**

| 参数            | 取值示例                              | 说明                                                         |
| :-------------- | :------------------------------------ | :----------------------------------------------------------- |
| `width`         | `device-width` 或具体数值（如 `640`） | 视口宽度。一般设为 `device-width`，即设备屏幕的物理宽度。    |
| `initial-scale` | `1.0` ~ `10.0`                        | 页面首次加载时的缩放比例。`1.0` 表示无缩放。                 |
| `minimum-scale` | `0.5` ~ `10.0`                        | 允许用户的最小缩放比例。                                     |
| `maximum-scale` | `0.5` ~ `10.0`                        | 允许用户的最大缩放比例。                                     |
| `user-scalable` | `yes` / `no`                          | 是否允许用户通过手势缩放页面。`no` 会禁用缩放（不推荐无理由禁用，影响可访问性）。 |

## meta的四个属性

- http-equiv 【重要关键词】
  - content-type
    - 定义字符编码 默认是UTF-8 **如果浏览器出现乱码可以检查一下字符编码类型是什么**
    - 不推荐使用 改用charset 属性
  - refresh：指定以秒为单位，执行重载和重定向
- name 【 重要关键词】
  - application-name：应用程序名称
  - keywords ： keywords用来告诉搜索引擎你网页的关键字是什么
  - author ： 当前页的作者名
  - viewport
    - 设置浏览器视口
    - 重要关键字
      - width ： 视口宽度
      - *-scale （initial-scale）： 缩放相关
      - user-scalable ： 是否可以手动缩放
      - 例如：<*meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1"* >
- description description用来告诉搜索引擎你的网站主要内容
- content ：具体描述 、不能单独存在
- charset（HTML5）：推荐使用 utf-8 简化了不同脚本对文件中字符的处理

**meta标签的作用**

1. 搜索引擎优化（SEO）
2. 定义页面使用语言
3. 自动刷新并指向新的页面
4. 实现网页转换时的动态效果
5. 控制页面缓冲
6. 网页定级评价
7. 控制网页显示的窗口

# link和@import的区别

1. **资源加载方式：并行下载 vs 串行下载**
   `<link>` 引入多个 CSS 文件时，浏览器会**并行下载**，所有请求同时发出互不阻塞。`@import` 则是**串行下载**，后一个 CSS 文件必须等前一个下载并解析完成后才开始，加载效率较低。

2. **DOM 可操控性：可控 vs 不可控**
   `<link>` 是一个标准 **DOM 标签**，可通过 JavaScript 动态创建、修改或删除，例如设置 `rel`、`href`、`media` 等属性来实现按需加载或用 `disabled` 属性切换样式表。`@import` 是 CSS 语法规则，写在 CSS 文件中，**无法通过 JS 直接操控**，也无法动态切换。

3. **书写位置与作用域**
   `<link>` 写在 HTML 的 `<head>` 中，作用于整个文档，且支持 `media` 属性（如 `<link media="print">`）做条件加载。`@import` 必须写在 CSS 文件或 `<style>` 标签的**最顶部（所有规则之前）**，只能在 CSS 上下文中使用，不支持条件加载。

4. **浏览器兼容性与解析优先级**
   `<link>` 支持所有浏览器，浏览器将其视为**高优先级资源**（关键渲染路径的一部分）。`@import` 在旧版 IE（IE 5-8）中存在兼容问题，且浏览器对其解析优先级较低，还可能**阻塞主线程的 DOM 构建**（因为遇到 `@import` 时需要等待串行下载完成）。
